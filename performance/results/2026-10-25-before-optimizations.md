# Производительность Nether и Rust — 2026-10-25

Замер текущего NMM 0.1 с MIR verifier. Сравнивается рабочее дерево с незакоммиченными изменениями; commit и SHA-256 исходников компилятора сохранены в [сырых данных](2026-10-25.json).

Среда: macOS 26.6.2, arm64, rustc 1.86.0. Модель CPU недоступна из sandbox. Оба варианта используют opt-level=3, без LTO и с отключёнными проверками переполнения. 1 прогрев и 7 измерений каждой программы, порядок Rust/Nether чередуется. Время — wall-clock процесса, включая его запуск; основная метрика — медиана.

## Компиляция и размер

Медиана 3 повторных полных сборок каждого исходника с прогретым файловым кешем. Для Nether включены frontend/checker/verifier, генерация Rust, rustc и линковка; сборка самого компилятора Nether исключена. Размер — полный неочищенный executable, включая runtime и метаданные, не только машинный код.

## Интерпретация

- `array_sum`, `lcg`, `struct_step`: в этом прогоне близкие времена. Разницу в несколько процентов нельзя считать устойчивым преимуществом по одному запуску серии.
- `collatz` — около 1.83× Rust, `fib` — около 1.95×. Это сохраняющиеся направления оптимизации backend. Возможные причины — Result/Fault ABI, CFG dispatcher и проверки деления; причинный вклад каждой здесь отдельно не измерялся.
- `class_alloc` использует `black_box` только в Rust, чтобы препятствовать удалению аллокаций. Результат около 1× относится к этому искусственному ограничению оптимизации, а не к общему равенству программ.
- `class_alloc_elidable` содержит тот же Nether и Rust без `black_box`. Здесь наблюдается 44.79× end-to-end разница: Rust значительно лучше оптимизирует этот исходник. Короткое Rust-время чувствительно к запуску процесса; точный коэффициент не является оценкой стоимости одной аллокации. Подсчёт сохранённых аллокаций в этом прогоне не выполнялся.

## Ограничения и воспроизведение

Запуск из корня: `./performance/run.sh 7 --build-runs 3`. Требуются Python 3, cargo/rustc; внешних Python-пакетов нет. Новые измерения и бинарники попадают в игнорируемую папку `performance/out/`. Ненулевые вычисленные коды выхода допустимы; signal termination, ошибка сборки и несовпадение результатов останавливают запуск.

Это 7 микробенчмарков на одном хосте, без изоляции CPU и контроля фоновой нагрузки/температуры. Проверки переполнения, peak RSS, большие приложения, generics/interfaces, коллекции и многопоточность не измерены. Время компиляции включает линковку и не разделено по стадиям. Порогов производительности для CI нет.
