# Порядок root cleanup

Редакция 2026-10-25. Частное правило единственной [NMM](../../core-memory-managment.md)
для Nether 0.1; альтернативных вариантов здесь нет.

Каждый текущий owned lifetime занимает позицию по последней успешной
инициализации root. Replacement обновляет её после commit. При выходе roots
очищаются в обратном порядке; запись поля позицию root не меняет.
Для `var a = Resource(1); let b = Resource(2); a = Resource(3)` журнал
destructors: `[1, 3, 2]`. Move исключает старый root из cleanup; неуспешный RHS
не считается успешной инициализацией. Panic и обычный выход используют один контракт.
